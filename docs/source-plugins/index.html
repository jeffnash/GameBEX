Source plugins

Turn a compatible ROM site's catalog into a library you can browse with a controller. Use the prompt below to have your coding agent write the plugin.

Browse a compatible ROM site’s catalog inside GameBEX, search for a game, and add it to your download queue with a controller. A source plugin is the JSON file that tells GameBEX how to read that site. You can write one, import one someone shared, or use the prompt below with a coding agent.

The app calls plugins Game sources. It ships with no plugins, catalog, or games, so Discover stays empty until you add one. GameBEX doesn’t operate, endorse, or verify any plugin or the site behind it.

Before you import anything

What you import, and what you download through it, is your decision and your responsibility. Only use sites you have the right to use, and only play games and firmware you legally own. See Legal.

Import a plugin and play

Section titled “Import a plugin and play”

  1. Import. Go to System → Device → Game sources → Import source and pick the .json file. GameBEX checks it before anything is installed and rejects a file it doesn’t understand.

  2. Read the label. The import screen shows the plugin’s name, version, and author, and marks the author unverified. When a file replaces a plugin you already have, the screen lists every new domain the update wants, and if you back out, nothing changes.

  3. Browse. Discover fills with the site’s consoles, latest additions, and search, and you move through it with the D-pad like every other screen.

  4. Download. Press A on a game to add it to the download queue. If you disable or remove the plugin mid-download, the download pauses until you retry it.

  5. Prep. GameBEX unpacks archives, checks .cue, .gdi, and .m3u sheets, builds a playlist for multi-disc games, and checks BIOS files against known checksums. Anything it can’t fix on its own is named on the game page, and Formats & disc prep has the details.

  6. Play. The button on the game page now says Play.

Which sites a plugin can contact

Section titled “Which sites a plugin can contact”

Each plugin lists the domains it may contact for each job, and GameBEX checks every request against that list, including redirects. Here is an example using a made-up domain:

The author field is a name supplied by the plugin, not a verified identity. The four purposes are:

Purpose Used for
catalog Consoles, browsing, search, and game details
download The file transfers themselves
artwork Cover art, loaded only through that plugin’s own image loader
assist Browser verification, and only if the plugin turns it on
  • Every request URL, including every redirect hop, has to match the list for its purpose, so a redirect to cdn.somewhere-else.com is refused, and so is http://roms-i-own.com.
  • Requests use HTTPS on the default port with no credentials in the URL, and DNS answers must be public addresses.
  • A plugin can’t set cookies or authorization headers, and it can’t pick file names, folders, or volumes, because GameBEX decides where everything goes.

What never depends on a plugin

Section titled “What never depends on a plugin”

Your library, BIOS files, emulators, and downloaded games all work with zero plugins installed. BIOS checks, emulator installs, RetroArch cores, and ScreenScraper covers are built into GameBEX. Plugins are data only, and GameBEX never bundles, installs, or updates them on its own.
